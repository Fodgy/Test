**Засвоєні методи/патерни:** дедублікація списку через `set()`, `.issubset()`, `.issuperset()`, `.isdisjoint()`, методи `.union()/.intersection()/.difference()`, `.update()`, `frozenset`, set comprehension, оптимізація пошуку через перетворення списку в множину.

**Типові підводні камені:**
- звичайна множина (`set`) НЕ хешована і не може бути елементом іншої множини чи ключем словника — для цього потрібен `frozenset`;
- `set(list)` не гарантує збереження порядку елементів — якщо порядок важливий, потрібен інший підхід (наприклад, `dict.fromkeys()`);
- перевірка `x in list` працює за O(n), а `x in set` — за O(1) в середньому; для великої кількості перевірок належності множина значно ефективніша.

**Контрольна задача (без коду):** Дано список email-адрес користувачів, які підписались на розсилку A, і список email-адрес, підписаних на розсилку B. Знайди адреси, підписані РІВНО на одну з двох розсилок (не на обидві одразу), використовуючи операції множин.

Реалізуй через перевірку "видали вершину, порахуй компоненти через множини/BFS, порівняй з вихідною кількістю" для кожної вершини (простий, не найефективніший підхід — O(V*(V+E)) прийнятний для навчальних цілей).

**Очікуваний результат:** Множина точок зчленування, наприклад `{3, 4}`.

**Приклад:**
```text
Input: [(1,2),(2,3),(3,1),(3,4),(4,5)]
Output: {3, 4}
```

## Progress Check 5 (після задач 48–55, фінал теми Sets)

**Засвоєні методи/патерни:** повноцінний Union-Find зі стисненням шляху, оптимізація N-ферзів через множини атакованих ліній, виявлення спільнот/зв'язних компонент у великих графах, наближені алгоритми для NP-складних задач (Vertex Cover), Bloom filter, articulation points.

**Типові підводні камені на цьому рівні:**
- забування стиснення шляху (path compression) в Union-Find різко погіршує продуктивність на великих графах;
- плутанина між "точним" і "наближеним" розв'язком NP-складних задач (Vertex Cover, Steiner Tree) — важливо усвідомлювати, що жадібні алгоритми дають ПРИЙНЯТНИЙ, але не завжди ОПТИМАЛЬНИЙ результат;
- у Bloom filter забування, що структура може давати хибно-позитивні результати (каже "можливо є", хоча елемента немає), але НІКОЛИ хибно-негативні (якщо каже "немає" — то точно немає).

**Фінальна контрольна задача теми (без коду):** Дано список "маршрутів" авіакомпанії у вигляді пар (місто_відправлення, місто_призначення). Використовуючи множини та Union-Find, визнач: (1) чи можна долетіти з будь-якого міста в будь-яке інше (мережа повністю зв'язна, вважай маршрути двонаправленими), (2) якщо ні — скільки окремих "кластерів" міст утворилось і які міста входять до найменшого з них.
